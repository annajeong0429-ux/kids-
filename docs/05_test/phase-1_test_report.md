## 2. 이슈 상세

### 🟠 주요

#### BUG-P1-01 🟠 마스크 보유 범위 등 "안심존에서 먼저 확인할 사항"을 확정 사실로 적었고, 결과·PQ가 없음
- **위치:** PRD 1-4 (🔒 표시), 4-1 H1·H2·H-CLS, 8장 PQ 목록
- **문제:**
  1. 1-4는 "아토피피부염 10,166장에 EASI 4징후와 **피부/병변 분할 마스크**, iga_grade가 함께 있다"를 🔒(확정)로 적었다. 그러나 제안서는 마스크가 "아토피 중심(건선·정상 일부)"이라고만 하고, "**실제 마스크 보유 범위는 본선 진출 시 안심존에서 최우선으로 확인할 항목**"이라고 했다. H1·H2·F-13 전체가 이 전제 위에 있다.
  2. 사전학습 가중치(EfficientNet-B0) **반입 허용 여부**는 제안서가 "8월 중 확인"하기로 한 사항인데(표 15), PRD에는 결과가 없다. H1 방법이 둘로 갈려 있어 K-01 달성 가능성이 달라진다.
  3. **iga_grade 등급 수 불일치:** 제안서 2.1은 중증도를 4구간(거의 없음 2,087·경증 3,613·중등도 2,792·중증 1,674)으로, 표 3·4.3.3은 iga_grade를 0~4(5등급)로 적었다. H2(등급별 단조성)의 등급 정의가 원천 안에서 맞지 않는데 PRD는 0~4만 적었다.
  4. **정상 피부 6,880장 처리:** H-CLS는 40종을 4개 군으로 나누는데, 정상 피부를 별도 클래스로 둘지·제외할지가 없다. 웹앱 F-18에서 정상 사진이 들어왔을 때의 동작에도 영향이 있다.
- **근거:** 제안서 2.2 "적용 범위의 한정"(p6~p7), 6장 표 15 "환경 사전 확인"(p21), 2.1(p5), 표 3(p6), 4.3.3(p13), 8.3 "세그멘테이션 라벨의 편중"(p25)
- **기대:** 1-4는 "⚠️ 안심존에서 확인 필요" 또는 확인 결과를 근거와 함께 기재. 확인 전이면 PQ(또는 대회 첫 과제)로 올린다.
- **실제:** 🔒로 단정, 반입 결과·등급 정의·정상 클래스 처리 언급 없음.
- **담당:** prd-agent

#### BUG-P1-02 🟠 K-02(H2, 최우선 지표)의 통과 기준이 측정은 되지만 판정력이 없음
- **위치:** PRD 5-1 K-02, 3-1 G-02
- **문제:**
  1. 기준이 "유의수준 0.05에서 유의하게 증가"뿐이다. 아토피 이미지가 약 1만 장이면 아주 약한 경향(예: Spearman ρ = 0.05)도 유의하게 나온다. "지표가 임상 중증도를 반영한다"고 주장하려면 **효과 크기 하한**(예: ρ ≥ X, 인접 등급 간 중앙값 차이)이 필요하다.
  2. 면적 비율을 **정답 마스크(lesion_area)로 계산하는지, 학습한 분할 모델의 예측 마스크로 계산하는지** 적혀 있지 않다. 정답 마스크로 보면 "지표 자체의 타당성", 예측으로 보면 "모델 + 지표의 타당성"이라 의미가 다르다 (둘 다 보고하는 것도 선택지).
  3. PRD는 "(검정 방법은 이 PRD가 구체화 ⚠️ — 팀장 확인)"이라고 적었지만 **8장 PQ에 해당 질문이 없다.** CLAUDE.md 1장 규칙상 원천 문서에 없는 방법을 채웠다면 팀장 확인이 필요하다.
- **근거:** 제안서 표 10 H2 "등급이 높을수록 면적 비율이 유의하게 증가"(p16), 4.4 "데이터 한계와 검증 전략"(p15)
- **기대:** 효과 크기 기준 + 마스크 출처 + 검정 방법을 PQ로 올려 확정.
- **실제:** 유의성만 기준, 마스크 출처 불명, PQ 없음.
- **담당:** prd-agent

#### BUG-P1-03 🟠 5-2 웹앱 지표에 측정 방법·시점·표본이 없음
- **위치:** PRD 5-2 K-11~K-17
- **문제:**
  1. 5-1 표에는 "측정 방법" 열이 있지만 5-2 표에는 **정의·목표만 있고 측정 방법·측정 시점·대상 표본이 없다.** CLAUDE.md 1장 ⑤ "측정 가능한 지표(KPI)와 측정 방법"을 채우지 못했다.
  2. K-13(비교 유용성)·K-15(의료진 유용성)은 설문이 필요한데, 설문을 어디서·누구에게·몇 명에게 하는지 없다. 특히 K-15는 의료진이 리포트를 보는 경로가 보호자 화면(F-10 진료 화면 모드)뿐이고 의료진 대시보드는 Non-goal이라, 응답을 모을 방법이 정의되지 않았다.
  3. K-14 "재진 전"은 F-04 재진일 입력이 없는 사용자를 어떻게 셀지 정의가 없다.
  4. PRD는 "베타 후 확정"이라고 적었지만 패키지는 "**목표값은 사용자 리서치(02) 후 확정**"이다. 또 PRD에는 베타(패키지: 보호자 20가정 4주) 계획이 없어 "베타"가 무엇인지 정해지지 않았다.
- **근거:** 패키지 01-6 성공 지표(p4), 12 WBS "베타 · 보호자 20가정 4주 사용 · 성공 지표 측정"(p28)
- **기대:** 지표마다 측정 방법(이벤트 로그/설문), 측정 기간, 표본, 데이터 출처를 적고, 확정 시점 문구를 원천과 맞춘다.
- **실제:** 정의·목표만 있음.
- **담당:** prd-agent

#### BUG-P1-04 🟠 추적성: 문제 → 기능 → 지표 연결이 끊긴 곳
- **위치:** PRD 9장, 3장, 5장
- **문제:**
  1. **기능 → 지표 연결이 아예 없다.** 9장에는 문제 → 기능, 목표 → 지표만 있다.
  2. **지표가 없는 기능·문제:** F-11(위험 증상 안내, P-02의 핵심) / F-18·F-19(웹앱, P-04) — K-04는 대회 모델 성능이지 웹앱 기능 지표가 아니다. P-02(과소·과다 내원)는 어떤 지표로도 측정되지 않는다 (5-3이 안전 지표 공백을 밝힌 것과 별개로 F-11 동작 여부도 지표·테스트 항목으로 없다).

#### BUG-P1-23 🟡 F-13 공개 조건에 K-03(4징후)이 빠짐

#### BUG-P1-24 🟡 F-18 감염성 하한 규칙은 PRD의 새 설계인데 제안 표시·PQ가 없음
- **위치:** PRD 4-2 F-18, 8장 PQ-06
- **문제:**
  1. "감염성 군 확률이 별도 하한을 넘으면(최고 확률이 아니어도) F-19 안내 대상"이라는 구조는 원천 문서에 없고 PRD가 새로 설계한 것이다. 근거로 단 제안서 8.2는 "애매하면 방문 고려"라는 원칙뿐이다. 1차 BUG-P1-06이 요구한 방향은 맞지만, ⚠️(제안) 표시나 PQ 없이 Must(조건부) 기능의 동작 규칙으로 들어갔다.
  2. "하한 값은 K-04 결과로 설정"이라고 했지만 K-04는 **병원 촬영 검증셋**의 결과다. 가정에서 찍은 스마트폰 사진(도메인 갭, 1-5)에서도 같은 하한으로 같은 재현율이 나온다는 근거가 없다. 누가 어떤 기준(목표 재현율)으로 하한을 정하는지도 없다.
- **기대:** F-18 규칙에 "⚠️ 제안 — PQ-06에서 확정"을 표시하고, PQ-06에 "하한 설정 방식(목표 재현율에 맞춘 임계값)과 도메인 갭 한계"를 추가.
- **담당:** prd-agent

#### BUG-P1-25 🟡 K-14·K-15 정의·표본이 패키지와 달라졌는데 변경 표시·근거가 없음
- **위치:** PRD 5-2 K-14, K-15, 4-3 패키지 대비 변경 표
- **문제:**
  1. K-14: 패키지 정의는 "재진 전 리포트를 연 사용자 비율"인데, v0.2는 "재진일 입력자 중 **재진일 전 7일 안에**"로 범위를 좁혔다. 측정은 더 쉬워졌지만, 목표값 50%는 옛 정의에 붙은 값이라 그대로 옮기면 의미가 달라진다. 4-3 변경 표에도 없다.
  2. K-15: "응답 의료진 **3명 이상**"은 원천에 없는 표본 기준이다. 3명이면 응답 1명이 33%p를 움직이므로 60% 목표로 판정하는 의미가 거의 없다 (2/3 = 67%면 통과, 1/3 = 33%면 실패). 대체 경로로 둔 "자문의·협력 의료진 인터뷰"도 팀과 가까운 응답자라 결과가 치우칠 수 있다.
- **기대:** 두 변경을 4-3 표에 "패키지 대비 변경 + 사유"로 기록하고 ⚠️ 제안을 표시한다. K-15 표본 기준은 PQ로 올리거나, "정성 지표(목표값 없음)"로 낮추는 선택지를 제시한다.
- **담당:** prd-agent

#### BUG-P1-26 🟡 4-1-2 "폐쇄망 모델 경량화"의 처리 사유가 원문과 다름
- **위치:** PRD 4-1-2 표 "폐쇄망 모델 경량화 (4.1)" 행
- **문제:** PRD의 처리 사유는 "서빙 비용은 웹앱 문제"인데, 제안서 4.1은 "**폐쇄망 환경에 맞춘** 모델 경량화"다. 목적은 안심존의 제한된 연산 자원·분석 시간에 대응하는 것이다 (4.3.1 "안심존의 제한된 분석 시간 안에서 유리"). 웹앱 서빙 비용과는 다른 문제라, 이 사유를 보고 팀장이 대회 Could로 내리는 판단을 잘못 이해할 수 있다. 결과보고서의 예·본선 일관성 설명에도 그대로 쓰일 사유다.
- **근거:** 제안서 4.1 본선 단계(p11), 4.3.1(p13)
- **기대:** 사유를 원문 목적에 맞게 고친다 (예: "안심존 연산 자원으로 학습이 가능하면 불필요 — PQ-10 ② 확인 후 결정").
- **담당:** prd-agent

#### BUG-P1-27 💡 F-18 실행 시점이 정해지지 않아 과잉경고(R-02) 가능성

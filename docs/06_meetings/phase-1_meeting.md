**PRD 에이전트 (목표·범위)**

- 범위가 늘어난 곳은 두 군데다: F-18(질환군 분류)·F-19(역학 정보, D-06), 그리고 F-13·F-14를 조건부 Must로 올린 것(D-05·D-11). 둘 다 팀장 결정에서 나왔다.
- RAG는 D-15에 따라 하지 않는다. 결과보고서에 예·본선 변경 사유로 적는다.

**테스트 에이전트 (남은 이슈)**
- 1차 검사(v0.1): 🔴 0 · 🟠 11 · 🟡 7 · 💡 3. 수치·인용은 원천 문서와 모두 일치했다.
- 재검사(v0.2): 21건 중 20건 해결, 1건 부분 해결. 새로 🟠 1 · 🟡 4 · 💡 2.
- 재검사에서 나온 이슈는 v0.3에 반영했다. **v0.3 이후 변경분(v0.3~v0.3.3)은 재검사하지 않았다.** CLAUDE.md 5장이 자동 수정-재검사를 최대 2회로 정하고 있어서다. 이후 변경은 팀장 결정과 Codex 지적 반영뿐이다.

## 안건 2. Codex 교차 검토 결과와 대응

- 지적 1건: CX-P1-01 [P2] 임계값 조정용 데이터와 최종 평가용 데이터를 나누라.
- 대응: **수용.** 데이터를 학습 / 임계값 조정 / 홀드아웃 3분할하고, K-01~K-04와 공개 기준은 홀드아웃에서만 재도록 했다 (D-19).
- 반론: 없음. Claude와 Codex 의견이 갈린 항목도 없음.
- **검토 방식에서 생긴 문제:**
  1. `/codex:review` 에는 지시문을 붙일 수 없다. PR diff에 테스트 리포트가 들어 있어 독립성이 깨질 수 있었다 → 테스트 리포트를 뺀 검토 전용 로컬 브랜치로 해결했다.
  2. Codex 출력이 AGENTS.md 형식(확인한 범위, CX ID)이 아니었다. "문제 없는 범위"를 알 수 없다.
  3. 기준 문서(PDF)를 실제로 참조했는지 확인할 수 없다.

## 안건 4. 이번 Phase 사이에 생긴 공백 — 11/6까지 에이전트 팀은 무엇을 하는가

- CLAUDE.md의 Phase 2~5는 웹앱 개발 흐름이다. 그런데 D-14로 웹앱은 11/9에 시작한다.
- 11/6까지의 핵심 작업은 안심존 분석이다. 안심존은 폐쇄망이고 전자기기 반입이 금지돼 있어 에이전트가 직접 할 수 없다.
- 에이전트가 미리 할 수 있는 일: ① 반입할 분석 코드베이스 준비 (3-헤드 모델 학습, D-18·D-19 기준 평가 스크립트, 시각화) ② 반입 패키지 목록 ③ 결과보고서·발표자료 틀.
- 의견: 이 작업을 별도 Phase("Phase C — 대회 분석 준비")로 넣을지, 비공식 지원으로 할지는 **팀장 결정 사항**이다. 합의된 결론은 없다 → 보고서 5장 결정 1.
